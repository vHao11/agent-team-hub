## 应当保持的业务条件

1. 一条事项同一时刻只有一个当前负责组。
2. 原组保持责任直到目标组接受转交。
3. 只有指定验收人能批准当前交付。
4. 老交付和旧需求版本不能关闭最新事项。
5. 相同操作重试不重复创建对象；同 ID 不同命令内容被拒绝。
6. 事件重放不意味着重新执行命令。
7. Agent 运行成功不直接产生业务完成。
8. 失联与取消请求均不被伪装成已确认终态。
9. 同一用户不同设备的绑定和运行记录可区分。
10. 工具集更新不改写已有 Run 的能力版本。

## 手动业务验收

以下流程使用明确标注的演示数据与演示身份：

1. 以请求方创建一条面向清算组的事项，填写至少一条验收条件。
2. 切换承接方，进入团队收件箱并接单。
3. 开始处理，更新进展、卡点和下一步。
4. 选取一个共享能力，检查版本与所需环境。
5. 关联实际本地会话，或通过已连接的执行适配器明确启动。
6. 回报执行结果，检查事项仍未完成。
7. 提交可读取的交付材料。
8. 切换指定验收人，先退回补充，再验收新交付。
9. 检查旧进展、交付版本和退回原因仍可查看。

未安装本机适配器时，第 5 步只验证会话关联路径，不能记作 Superagent 自动执行通过。
