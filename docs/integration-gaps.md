# 接入能力与待验证项

此文件区分仓库中可执行的通用功能与需要目标环境验证的宿主集成。服务源码版本：0.5.0；DSH 插件版本：0.5.1。

## 当前接入范围

| 路径 | 实现目标 | 验证要求 |
| --- | --- | --- |
| Web → HTTP API | 团队台账、并行流水线、跨步骤回退、接单、进展、交付、验收、工具目录 | 本仓库 API 测试及隔离演示数据浏览器实测 |
| CLI → HTTP API | 在终端或任意有命令执行能力的 harness 中操作同一台账 | 命令集成测试及实际服务 smoke test |
| MCP → HTTP API | 协作交付验收、流水线与回退、文本材料、目录发布、团队工具集与协议发现 | 官方 SDK → stdio → HTTP/SQLite 的双身份和跨组闭环已测 |
| Claude Code / Codex / OpenCode | 各宿主配置生成、标准 MCP、项目 Skill 安装入口 | 具体版本和实际连接/工具列举层级见 [宿主验证记录](harness-host-verification.md) |
| DSH → HTTP API | 25 个原生工具、连接配置、通用适配器加载 | Windows rc.1 隔离 profile 与真实 Superagent 验证；其他机器需各自验证 |
| 可替换看板 | 稳定外部键、独立订阅、状态投影、可选解除和自动对账；DSH 看板支持明确的反向业务命令 | Python 本地看板经跨语言协议与真实 Hub 通过两组流程；DSH 看板通过隔离宿主的反向审核流程 |
| 可替换执行器 | 版本与能力探测、显式启动或按流程自动派发、状态、取消及按派发 ID 恢复 | Codex、Claude Code 真实只读任务均已验证；其他宿主需真实适配器 |
| Superagent 自动执行 | 可选的本机管理 API 适配器；固定目录核验、请求去重 ID、固定能力内容投递、状态读取与停止确认 | 隔离真实 DSH 宿主中的后台子进程退出与两组并行汇合通过；自动确认目前限定已核验的 Windows DSH 0.2.2-rc.1 本机提供器，其他提供器、原生 CLI 引擎和无法追溯的运行保持未知 |

通用 CLI/MCP 可用不代表已经取得某个 harness 的自动启动、取消或恢复能力。独立界面可用也不代表已接入用户正在使用的 DSH profile。

不安装 DSH 的成员接入同一个 Hub，步骤见 [跨 Harness 接入](cross-harness.md)。脚本可通过通用 CLI 固定版本安装并显式执行；Skill 可安装到三种宿主的项目发现目录。其他能力类型的目录发布不等于统一安装、运行或部署已实现。

官方宿主实测的复现方法和结果见 [DSH 安装验证](dsh-installation-verification.md)。该检查使用临时 DSH_HOME、独立数据库和演示身份，未写入用户 Windows 或现有 profile。

## 原始发布时的宿主验证边界

- 用户现有个人待办看板的卡片 ID、数据接口和事件未取得。
- 用户增强 Superagent 的当前提交、公开 exports、消息入口和运行回调未取得。
- 本执行环境没有用户 Windows 上的 DSH 安装与 profile。

这些限制记录的是原始发布时的状态。后续已核对本机接口并完成上述实测；不同宿主和版本仍需分别验证。

## 看板接入需要的最小接口

| 能力 | 最小数据 |
| --- | --- |
| 探测 | 插件版本、是否支持稳定卡片 ID、是否能写共享关联 |
| 创建或关联 | work_item_id、稳定 external_ref、标题、本地工作区 |
| 返回绑定 | card_id、session_id（若存在）、适配器版本 |
| 更新 | 只更新共享目标、责任与验收状态等字段 |

本机 `dsh-todo-kanban` 草稿拥有稳定 `tb-...` ID；Cordis 服务使用 Hub 外部关联键，不使用标题、数组下标或备注作为主键。其他看板可通过 [通用接入协议 v1](adapter-protocol-v1.md) 提供同样的能力；使用前仍须验证实际稳定 ID 和受控关联行为。

## Superagent 接入需要的最小接口

1. 能力探测与支持的版本范围。
2. 提交一条显式运行请求，携带稳定 dispatch_id。
3. 返回已有或新创建的 ticket/session/run 句柄。
4. 查询当前状态，并区分入队、运行、等待人工和终态。
5. 请求取消并单独确认是否停止。
6. 在连接恢复后按句柄或 dispatch_id 找回执行。

缺少某项能力时，适配器声明该项不支持。不能以启动普通 DSH 会话冒充启动增强 Superagent，也不能通过直接改写其数据库完成接入。

## 在真实机器上的核验顺序

1. 记录 DSH 版本、运行 profile、看板插件版本和 Superagent 提交。
2. 构建并加载新插件，确认工具与连接状态。
3. 查询共享服务里的一个测试事项。
4. 关联一个本地待办，再次关联应得到同一结果。
5. 显式启动一次无外部副作用的测试任务。
6. 对照宿主真实会话检查状态和产物回报。
7. 验证断连恢复、取消回执和重复 dispatch 去重。
8. 用两台客户端验证不会因失联自动重复执行。

完成上述检查后，才能把对应 DSH 版本及增强版提交标记为已验证兼容。

## 发布范围

本仓库提供公开源码、示例、安装入口和测试；npm 发布以及升级各机器的正式部署仍是独立动作。正式环境中的业务数据、凭据和备份不属于公开源码。
